# Desktop integration and install/update delivery

Author: NewtTheWolf
Date: 2026-11-15
Status: implemented, with isolated verification and review in progress.
Native acceptance, signing and notarization remain separate checks.

## Complete operational scope

Provide explicit user-scoped Open With registration, explicit native desktop
notifications, and an install/upgrade/uninstall path for the already-built
portable release. No new settings screen, designer work, idle runtime, polling,
clipboard mutation or automatic upload is added. User files, chosen default
handlers, history and settings remain preserved when unregistering/uninstalling.

Exact new CLI grammar:

```
desktop associations status|enable|disable
desktop notify TITLE BODY
```

The root agent wires these commands in `main.rs`/`cli.rs` and must provide
`screenshots --open FILE` through the existing worker-side Open image path.
Desktop entries/registry commands use that argument, never a shell command.
Apple bundle document-open delivery also needs GPUI `Application::on_open_urls`
to route one file URL through the same worker; registering document claims
without actually accepting file-open events is not complete Open With support.

## Associations

Linux manages exactly `$XDG_DATA_HOME/applications/me.lejy.screenshots.desktop`,
falling back to `$HOME/.local/share/applications`. Paths must be absolute. The
entry advertises PNG, JPEG, WebP, BMP and TIFF with `Exec="ABSOLUTE_EXE" --open %f`.
Use Desktop Entry quoting, escaping percent signs in the executable. Registration
adds an Open With candidate, not a default-handler override. Do not edit
`mimeapps.list`. Run `update-desktop-database` only if available after the file
operation; report registration-file success separately from cache-refresh
failure. Final-path symlinks, FIFOs, foreign/edited entries and >16 KiB files
are conflicts. Enable is idempotent only for exact owned bytes; disable removes
only those exact bytes, with identity rechecks. Use atomic no-replace publication
and private temporary files, following existing autostart ownership rules.

Windows manages only its own HKCU `Software\Classes\Screenshots.Image` ProgID,
owned marker, `shell\open\command`, and this ProgID's named values below
`.png/.jpg/.jpeg/.webp/.bmp/.tif/.tiff\OpenWithProgids`. It never changes extension
defaults, UserChoice, HKLM or existing unrelated values. The command is quoted
as `"ABSOLUTE_EXE" --open "%1"`. Inspect bounded REG_SZ/REG_NONE values and refuse
foreign/edited owned registration. Removal deletes exact owned values; it leaves
empty registry keys rather than deleting a shared extension key. Register/
unregister notifies the shell that associations changed. Native
registry operations have ordinary OS failure behavior, not a hard-call timeout.

macOS registration uses an application bundle with CFBundleDocumentTypes,
Viewer role, Alternate handler rank and public PNG/JPEG/WebP/BMP/TIFF UTIs.
The bundle is generated by packaging; raw executable registration fails with
guidance to install the bundle. Register/unregister through the system
LaunchServices registration tool only for that exact bundle. Do not rewrite
another application's LaunchServices defaults. Runtime document-open, signed
identity and actual Finder behavior require native macOS acceptance.

Successful JSON is `{action, status, scope:"user_open_with"}` with optional
lossy-native registration path. Status is `enabled`, `disabled` or `conflict`;
Windows can also report `partial` after an interrupted owned registration.
macOS status reports `bundle_available`, not proof of current LaunchServices
registration, because a bundle claim alone cannot establish that state.
Operations report completed mutation if subsequent cache refresh/stdout fails.
No notification, Open With launch or file decode occurs just from registration.

## Explicit native notifications

`desktop notify TITLE BODY` permits title 1–128 and body 1–2048 UTF-8 bytes,
rejecting Unicode controls except ordinary body newlines. Validate arguments
before starting any process. Notification content is supplied only because the
explicit command was invoked; tests never call the user's actual notification
service. No automatic post-capture hook is implied by this command.

Linux uses the installed `notify-send` executable (Freedesktop Notifications)
with separate arguments and plain-text body markup escaping. macOS uses the
system `osascript` with a fixed `on run argv` script and separate title/body
arguments. Windows uses the installed system PowerShell with a fixed script,
WinRT ToastNotificationManager, XML text nodes (no string interpolation into
markup/script) and the invoking application's native AUMID, queried before
starting the helper. A packaged app retains its actual family `!Screenshots`
identity. Only an unpackaged process with the owned registration may fall back
to `me.lejy.screenshots`; a packaged process whose identity cannot be read fails
closed. Missing tools/identity/denied
service fail explicitly. Never invoke a shell containing user strings.

Run the notification helper in an operation-scoped process with null stdin,
bounded/discarded stdout and diagnostics, <=5 second deadline, child cleanup
and no retries. There is no resident process, timer or notification watcher.
Success means the helper accepted submission, not proof the user saw a toast;
OS policy, Focus Assist/Do Not Disturb and notification permission can suppress
presentation. Result JSON is `{status:"submitted", platform}` and does not echo
notification content. Stream overflow, timeout/nonzero exit and result-output
failure use fixed error descriptions without the message text.

## Installer and package artifacts

`screenshots-install` (crate `apps/installer`, shipped in every portable archive)
provides explicit `install PACKAGE ROOT`, `status ROOT`,
`rollback ROOT`, `recover ROOT current|previous` and `uninstall ROOT`, portable
across Linux/Windows/macOS. It validates the
existing archive/checksum/build-info contract, bounded regular archive entries
and exact target before creating a user-selected install root. It copies only
package-owned files to a new version directory, keeps the prior version for
rollback, and records an installation manifest containing hashes. Existing
foreign files/symlinks are never replaced. An existing owned install can upgrade
by staging the new version and atomically switching a small current-version
pointer after complete verification; status must identify interrupted staging
without deleting unknown files. Uninstall removes only files whose stored hash
and identity still match; modified files preserve the installation and report
conflict. Settings/history/exports outside the selected root are untouched.

Every mutation is serialized by an OS file lock for the normalized install
root: flock on Unix and a native byte lock on Windows. State/version validation
and publication happen under that same lock. Acquisition retries exist only
during the explicit operation and stop after ten seconds. A small owned lock
file remains beside the install root; unlinking it would let concurrent waiters
lock different inodes. There is no idle lock waiter or background updater.

Archive extraction and complete version preparation happen in a private sibling
directory on the install root's filesystem. Before durable intent, the first
install root remains empty and retryable; no `versions` directory or temporary
intent bytes are written inside it. An owned synchronized intent precedes
creation of that directory, publication of the staged version, and publication
of a pinned public key. State/intent, launcher and public-key temporary files
also live beside the root. A key is fully written and synchronized before
no-replace publication, so an interrupted write cannot expose a partial final
key. `status` reports `recovery_required` even
when a first-install crash happened before the main state file was written.
Recovery can finish that first install, finish an upgrade, restore the prior
version, or finish/cancel an interrupted trust pin. Repeating the same pin
operation resumes its exact pending public key; a different key is refused.
The selected install root must share its parent's filesystem. An abrupt crash
before intent may leave a private sibling preparation directory or unpublished
temporary file; a retry does not treat it as installed state or delete it as
unknown data. Those files can be inspected and removed separately, without
blocking installation, recovery or uninstall of the managed root.

Uninstall also records intent before its first deletion. It retains a bounded
list of version IDs and one active owned manifest, checks each remaining file's
hash/type/identity before deleting it, and accepts already-missing owned files
only while resuming that intent. Unknown empty directories, FIFOs, sockets,
symlinks and modified files all stop removal and remain untouched. Repeat
`uninstall`, or use `recover ROOT current`, to finish after interruption;
deleted package files cannot be restored by selecting `previous`. This is
cooperative installer ownership, not atomic compare-and-delete against a
hostile process editing the same paths during the final unlink.

Build a real macOS `.app` bundle with Info.plist/document claims as part of
packaging. Linux desktop launcher and Windows registry registration remain
explicit commands; the installer does not silently enable startup or claim
default file types. `cargo xtask package-app` constructs an actual Debian `.deb`
with bounded ar/tar members written by the xtask, macOS `.app`
archive and native `.pkg` through pkgbuild, or Windows MSIX through the installed
SDK MakeAppx. MSIX file activation uses `--open "%1"`. The packages are unsigned
development artifacts; a production MSIX signature must match its publisher,
and macOS signing/notarization requires the real release identity. CI covers
Linux x86_64/ARM64, Windows x86_64 and macOS ARM64/Intel using native runners.
Those jobs establish only the results they actually complete; adding a matrix
entry does not establish native runtime acceptance.

## Authenticated update boundary

An updater must verify a signed bounded manifest and artifact digest before
staging; HTTPS/checksum alone is not artifact authentication. The release's
trusted public key must be pinned by trusted installation/build configuration,
with rollback/version/target checks and no arbitrary extraction paths. No
production signing key or trust root is available in this session. The installed
verifier/stager requires `pin-key ROOT PUBLIC_KEY` to pin an explicit local
Ed25519 public key. `update ROOT HTTPS_MANIFEST_URL` retrieves a bounded manifest
and detached `.sig`, authenticates exact private snapshots before trusting the
artifact URL, checks target/newer version/digest/size, streams a bounded artifact,
and authenticates a private artifact snapshot before parsing. Redirects and
proxies are disabled; no request or signature result is silently retried.
`apply-signed ROOT MANIFEST SIGNATURE ARTIFACT` verifies the same local inputs.
Tests use clearly separate synthetic signed fixtures. Never ship a generated test key
as the official trust root, pretend code signing/notarization succeeded, or
auto-download/apply an unauthenticated artifact. The final release owner must
provide the public signing identity and publish properly signed manifests.

The user-installer can apply a separately verified local package and retain
rollback. Online automatic update checking must be explicit/on-demand or use
native events, with no periodic idle polling. No periodic checker is installed.
Signing, notarization and actual
official feed publication are concrete external release inputs, not reasons
to leave registration, notifications or local upgrade logic unimplemented.

## Files and tests

Owned source: `apps/desktop/src/desktop_integration.rs` and, if useful, private
`desktop_integration_windows.rs`; new `apps/desktop/tests/desktop_integration.rs`.
Root owns main/CLI/Open-image routing. Packaging changes owned here:
`apps/installer`, `scripts/test-install-user.py`, bundle helper
`xtask/src/package_app.rs`, `scripts/test-package-app.py` and generated native
manifests. `cargo xtask package` includes the standalone installer and this
contract; `.github/workflows/rust.yml` runs installer/native package tests and
builds the corresponding native artifacts.

Tests isolate XDG/HOME/user paths. Verify exact registration quoting, enable/
status/disable/idempotence, edited/foreign/FIFO/symlink conflict preservation,
bounded reads and no notification. A fake notification executable records
argv and tests title/body escaping, capped streams, deadlines and no leaked
payloads. Windows tests use a unique HKCU test namespace or isolated Wine
prefix; no real extension defaults are changed. Bundle plist tests use native
plist parsing and actual file types/entry arguments. Installer tests build a
synthetic package and cover install, status, same-version idempotence, upgrade,
rollback, modified-file refusal, hostile paths, interruption and uninstall.
Native tests perform no user desktop capture, clipboard writes or secret access.

There is no idle resource cost. Active association operations use one <=16 KiB
entry/registry value, notification helpers use <=16 KiB diagnostics and one
operation-owned child, and installation streams bounded archive members rather
than reading a whole release into RAM. Encoded packages are at most 512 MiB,
expanded bytes at most 1 GiB, files at most 10,000, path metadata at most 1 MiB,
ZIP central metadata at most 16 MiB and individual tar PAX metadata at most
64 KiB. At most 128 package versions are retained; reaching that limit refuses
a new version rather than deleting older files implicitly. Each version
manifest is at most 4 MiB; uninstall holds one active manifest plus at most
32 KiB of intent bookkeeping. Private artifact snapshots add bounded temporary
disk use, not a full-release RAM buffer. Measure release invocation costs and
keep native OS/service/signing acceptance separate from synthetic checks.

Twenty-one isolated installer fixtures passed (the dangling-symlink fixture is
Unix-only), including actual child-process
crash points after extraction, partway through an intent write, before creation
of the version directory, before first state publication, partway through a
public-key write, after public-key publication and
after the first uninstall deletion; repeated interruption during prior-version
recovery and terminal uninstall; journal retention after a dangling-symlink
conflict at the terminal uninstall step; a real OS-lock concurrent-upgrade race;
foreign empty-directory/FIFO preservation; and a local HTTPS signed update
that refuses to fetch the artifact after a bad manifest signature. Three native
manifest/bundle/Debian layout fixtures and seven portable packaging fixtures also
passed. These do not claim production signatures or native OS installation.

An empty or absent install root reports `not_installed`. Repeating uninstall or
`recover current` succeeds without deleting an unowned empty directory. This
also covers interruption between the last intent removal and root removal.
Recovery accepts the exact prior-version state it can itself publish, so an
interruption during recovery permits either choice on the next attempt.

Windows portable packaging additionally requires the pinned vcpkg installation
and `x64-windows-static-md` triplet used by the SFTP engine. It includes the
native curl, libssh2, OpenSSL and zlib `share/*/copyright` files alongside the
existing Cargo dependency notices, with their vcpkg baseline recorded. Admission
and copying each require a regular notice of at most 1 MiB; missing, oversized,
symlink or FIFO inputs refuse packaging. These are static-library notices;
no additional DLL payload is inferred or bundled. An isolated synthetic archive
fixture verifies all four native notices and preservation of Rust notices.
