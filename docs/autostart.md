# Linux user autostart

Manage the current executable's entry for the next desktop login:

```sh
screenshots autostart status
screenshots autostart enable
screenshots autostart disable
```

These explicit commands do not open a window or capture pixels. `enable` writes
an XDG desktop entry which runs the canonical absolute path of the invoking
executable with `--show` after a subsequent login. This opens the normal application
window; Linux hidden tray/resident startup is not implemented by this feature.
The desktop environment must support and permit XDG autostart. Enabling does not
start the application immediately or guarantee successful login-time launch.

The managed file is
`$XDG_CONFIG_HOME/autostart/me.lejy.screenshots.desktop`. If `XDG_CONFIG_HOME` is
unset or empty, it uses `$HOME/.config/autostart/me.lejy.screenshots.desktop`.
Configured base paths must be absolute. Path operations retain native bytes;
JSON displays paths lossily and labels this with `path_encoding`.

Successful commands emit one JSON object, for example:

```json
{"scope":"managed_user_entry","status":"enabled","path":"/home/user/.config/autostart/me.lejy.screenshots.desktop","path_encoding":"lossy-native"}
```

`status` is `disabled` when this user entry is absent, `enabled` only when it
exactly matches the entry generated for the current executable, or `conflict`
when the path contains another file, an edited entry, a directory, a symlink or
another special file. These states describe this managed user entry only. The
command does not inspect or disable system-wide autostart entries, other names,
desktop session restoration or startup programs; `disabled` is not a claim that
the application cannot start at login. In particular, removing a user entry can
expose a system-wide entry with the same name. No `Hidden=true` override is added.
Configuration, permission or filesystem errors use the normal CLI error result:
stderr, exit status 1 and no success JSON. Other platforms explicitly report that
this command supports Linux only.

Ownership is deliberately strict: the marker and every generated byte must
match. `enable` is idempotent for that exact entry and otherwise refuses to
replace an existing path. `disable` removes only the exact entry and is
idempotent when absent. Edited files and entries for an older executable path
remain untouched and report conflict; inspect and move them manually before
enabling from another installation. Moving or removing the installed binary can
leave an existing desktop entry unable to launch it.

The desktop `Exec` argument is quoted as one executable path; quote, backslash,
dollar and backtick characters are escaped, and literal percent signs are
doubled rather than treated as desktop field codes. It does not invoke a shell.
Non-UTF-8 executable paths, control characters and `=` are rejected before any
write. The rules follow the [Desktop Entry Exec specification](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html).
The login behavior and distinction between user and system entries follow the
[XDG Autostart specification](https://specifications.freedesktop.org/autostart/latest/).

Reads are bounded to 16 KiB plus one byte for growth detection. The final entry
must be a regular file, with nonfollowing, nonblocking open and opened-handle
checks. Creation writes a private temporary file, synchronizes it and publishes
with a no-replace hard link. New directories request mode 0700 and the entry
mode 0600, subject to the process umask; existing directory permissions stay as
they are. The containing filesystem must support this hard-link publication.
Completed mutations and directory synchronization failures are reported honestly.
An abrupt interruption can leave a `.screenshots-autostart-UUID.part` file next
to the entry; it is not an autostart desktop file and is never launched by this
command.

Before removal, identity, size and modification/change times are rechecked to
catch an ordinary concurrent edit or replacement. This is not atomic
compare-and-delete: a hostile process changing the same path between the final
check and unlink is outside this cooperative ownership guarantee. Avoid editing
or swapping the entry while an autostart command runs. Parent directory symlinks
follow normal filesystem semantics; the final entry symlink is always refused.

There are no watchers, resident threads, timers, scheduled jobs, image buffers,
network requests or new runtime dependencies. Work occurs only while one command runs;
the generated entry is inert until the desktop environment handles a login.
Tests use isolated temporary XDG/HOME paths and never enable the real user's
autostart entry. Native login behavior and reference-hardware startup/resource
budgets remain separate acceptance work.

Optimized Linux checks passed two unit fixtures for exact quoting/rejection and
four executable fixtures for enable/status/disable, idempotence, foreign and edited
entries, FIFO/symlink/directory/size conflicts, environment fallback and invalid
arguments. The generated ordinary-path entry also passed `desktop-file-validate`.
These checks never launched the generated entry or changed the real user's
autostart directory. The unsupported-platform fixture awaits Windows/macOS CI.
