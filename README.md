# screenshots

Open-source native desktop capture and sharing application built with GPUI Kit. English is the default UI language. Native system dialogs and OS error messages follow the operating system language.

Windows renderer lifecycle and its explicit release probe are documented in [control-window latency](docs/control-open-latency.md). The pinned Windows GPUI backend includes a small [local teardown patch](vendor/gpui-pre-windows/LOCAL-PATCH.md); build through this workspace so Cargo applies the override.

The [region-selection release probe](docs/region-latency.md) measures native Ctrl+Shift+R delivery through capture and compositor synchronization, with 101 real capture/cancel cycles. Its explicit test injects keyboard input; leave keyboard and clipboard untouched while running it. Normal launches contain no probe instrumentation.

On Windows, normal launches share one instance per user/session. Starting the app again signals the running instance to show its control window and exits before creating another tray icon or registering hotkeys. Instance setup/notification failures do not fall back to launching a second owner. A newly created control window is explicitly shown, including after a launcher started the resident app hidden. Explicit resource-probe modes and isolated GUI tests bypass this product lifecycle.

## UI implementation

The UI depends on `gpui-kit = 0.9.1`, which pins a matching GPUI 0.3.12 family.
The workspace commits Cargo.lock and CI uses `--locked`. Standard controls and
window-level focus/menu facilities come from Kit. Capture, image operations,
SQLite, credential storage and uploads remain in the existing Rust core.
See [the implementation and verification notes](docs/ui-redesign.md).

## Capture home

**Settings → Capture output** saves the behavior for quick region, delayed region,
display and window captures, including their tray/global-shortcut commands:

- **Copy only:** copies pixels without PNG/history output. One last image stays
  in memory for Edit, Copy or Save As; an older saved path is not reused.
- **Save only:** writes PNG/history and leaves the clipboard unchanged.
- **Save and copy (default):** preserves the existing quick-capture workflow.
- **Annotate first:** opens the captured image in the editor; region capture first
  asks for a selection. Nothing is copied or saved until an explicit editor output.
  Cancel preserves the previous capture and clipboard.

Changes apply only after settings save succeeds. Folder, appearance and shortcut
changes preserve the chosen profile. **New screenshot** always opens the frozen
editor, and its explicit Copy/Save buttons retain their own behavior. Copy only
and Annotate first require one image: with multiple monitors, **All displays** is
unavailable for these profiles. Use a chosen display/window or a single region.
Save only and Save and copy can still save all displays separately; the latter
copies the last image as before. Uploads remain a separate explicit action.

On Windows, **Settings → Global shortcuts** configures Primary display, Quick
region, Capture and annotate, Active window and Repeat last region. Enter a combination such as `Ctrl+Alt+Q`, leave
it empty to disable the command, then choose **Save shortcuts**. **Restore defaults**
saves the original Ctrl+Shift+S/R/E bindings and disables Active window and Repeat last region. Supported keys are letters, digits,
F1–F24 and PrintScreen; modifiers are Ctrl, Alt, Shift and Super (Windows key).
Letters/digits require Ctrl, Alt or Super. Duplicate bindings and OS conflicts
leave the previous working bindings in place. New keys are reserved until settings
save succeeds; a failed save keeps the previous keys. Active bindings are listed
separately from the editable fields. If native cleanup fails, the app reports the
remaining bindings and requires a restart before another change. Settings persist
across restarts and folder/theme changes. Non-Windows shortcut configuration is
not implemented. These settings do not change the existing capture output behavior.

**Active window** is a Windows capture command. Assign its initially disabled
shortcut in Settings, focus the desired application's window, then press that
shortcut. The target is recorded before this app hides windows or attaches its
editor; changing focus afterward does not select a different target. The saved
capture output profile applies, including Annotate first with no automatic output.
Capturing this app's own windows, the desktop or taskbar is refused.

The **Capture menu → Active window in 3 seconds** and matching tray command give
you time to focus the target window. Cancel countdown/Escape in the control window,
closing that window, or Quit cancels the countdown. A missing, minimized, closed
or changed-process target fails without falling back to the desktop. Foreground
focus/hotkey interaction and DPI acceptance remain separate manual checks.

**Exact region:** open **Displays & windows**, enter X, Y, Width and Height in
physical pixels, then choose **Exact region** for the desired display. Coordinates
start at that display's top-left corner, regardless of its desktop position or DPI.
The rectangle must fit entirely inside the display. The worker rejects changed
display geometry rather than capturing another area. The current output profile
applies; successful capture becomes the session's last reusable region on Windows.
To keep a rectangle, enter a **Preset name** and choose **Save / replace preset**
for a display where it fits. Up to 16 templates are saved across restarts; saving
the same name replaces it. **Use** fills the fields without capturing, then you
choose the target display explicitly. **Remove** deletes only the template.
Templates contain the name and rectangle, with no monitor identity or image data.
The input fields themselves are temporary.

**Repeat last region** is available on Windows in Recent capture, the Capture menu
and the tray after selecting a reusable region. Its optional shortcut starts
disabled. The app remembers one monitor-local pixel rectangle for the current app
session only, without retaining desktop pixels or writing coordinates to settings.
Quick-region selection remembers the area after a successful crop, including when
Annotate first opens the editor. Cropping a fresh full-display snapshot in the
editor also remembers the area when you explicitly output the edited image.
Imported, already cropped or rendered images are not treated as display coordinates.

Repeat uses the current output profile and checks the selected display's position,
resolution, DPI scale and rotation on the worker before and after capture. A changed
or missing display requires selecting a new region; it never falls back to another
display. Canceling before completing a selection preserves the previous area.
Canceling an editor opened after quick-region selection keeps that already chosen
rectangle, while producing no image output. Quitting forgets the rectangle.

The native GPUI workspace has three appearances: **Dark**, the default (neutral charcoal surfaces, grayscale controls and minimal decoration); **Oldschool** (compact task navigation, blue selection, colorful function icons and square controls); and **Classic** (One Dark workbench chrome on Kit: titlebar, page tabs, 240px dock, status bar; editor `#282c33`, panels `#2f343e`, accent `#74ade8`). The window title bar is Kit `TitleBar` and follows the selected appearance. Classic uses a 33px solid caption, Kit pane tabs, a segmented status bar and the same 16px rem as Dark so body copy stays readable. Choose one under **Settings → Appearance**, or use the theme button in the workspace header. Changes apply immediately across the control window, editor, text inputs and region guide. Appearance saves on a worker alongside the capture folder; failures restore the previous theme and show an error. New installations, settings without a theme, and retired or unknown theme values use Dark. An explicit Oldschool or Classic choice is preserved. Annotation colors and exported image pixels are independent of the UI theme.

**New screenshot** starts capture with annotation. **Capture menu** expands quick region, a three-second delay, and primary/all displays. **Recent capture**, **Library**, **Displays & windows**, **Uploads**, and **Settings** are directly accessible in the sidebar. Recent capture has a primary region command and a compact quick-capture list; the latest image keeps Edit, Copy, Save As and Show File together. Library loads one bounded metadata page on entry; filters, prefix search, PNG import and multi-selection remain available. Click an image name for its on-demand bounded preview. **More** groups Open, Show in folder, Upload PNG, Relink PNG and Remove from library; removing a reference keeps the PNG. Switching pages cancels stale history/preview requests and releases their data; active uploads continue.

Use **Ctrl+N** for a new annotated screenshot, **Ctrl+1** for Recent capture, **Ctrl+2** for Library, **Ctrl+3** for Displays & windows, and **Ctrl+,** for Settings (Command on macOS). Keyboard focus, hover and pressed states are shared across commands. Display/window entries are keyboard accessible as well. The control window starts at 1060×760 logical pixels with a 680×480 minimum. Compact windows keep their content at its natural height and scroll, rather than squeezing controls. Kit Sidebar, Button, Input, Checkbox, RadioGroup, Menu and Kbd components share the same semantic theme. Lucide icons are bundled locally; no remote fonts, webview or JavaScript runtime is used. Design and verification notes are in [the UI redesign notes](docs/ui-redesign.md).

The overlay and standalone editor share a grouped Kit-button toolbar: Select/Crop, drawing, labels/highlighting, and privacy effects. Buttons carry accessible labels and visible keyboard focus borders; hover tooltips name the tool and its shortcut. Copy, Save and Save & copy have a separate action row. Color uses actual swatches, and selection commands appear only when a mark is selected. The toolbar measures its content height, reserves image space in the standalone editor and scrolls when it reaches 60% of the available window height. Controls use a selected subset of bundled Lucide icons. The document canvas and bounded source-label editor remain application-owned so image/undo/byte limits are preserved. The native `editor_toolbar_visual_probe` explicitly creates synthetic pixels and captures only its own editor window at two sizes into `target/ui-preview`; it never captures another application's content or changes the clipboard.

Open the control window with `cargo run --locked -p screenshots -- --show` (Windows otherwise starts in the tray). The home screen offers region selection, primary/all displays, individual displays and window capture. The last capture has a bounded preview, recopy and **Show file**. Technical controls are under **Diagnostics**.

New captures use the user's Pictures/Screenshots folder by default (application config storage is the fallback if no Pictures directory is available). **Change folder…** opens the native directory picker and persists the selection in the platform application's `settings.json`. A canceled or failed change preserves the previous folder. **Export settings** writes appearance, folder, shortcuts, output profile, region presets, JPEG quality, Save as format, filename template, capture delay, per-task destination names and the strip-metadata-on-upload choice to a JSON file you choose; existing files are never overwritten. **Import settings** replaces `settings.json` from such a backup. If the backup folder is missing, the active save folder is kept. Upload destinations, history, images and secrets stay out of the file. Import never starts an upload. Settings load/save run on workers; capture is disabled while settings are loading/changing. Existing files under `target/captures` are left in place. Hardware tests keep their isolated test directories and do not read or alter user settings.

**Settings → Capture filename template** customizes automatic PNG names, including
edited/selected captures. For example, `Shot-{date}_{time}` uses UTC save date/time.
Use letters, digits, spaces, `-` or `_` and those two tokens; paths/extensions are
not allowed. A unique suffix and `.png` are always appended. Click **Save filename
template** to apply; an empty value restores default names. Existing files and
manual **Save as** names are preserved.

**Library → Open image…** opens PNG, JPEG or WebP directly in the editor without
importing it. The original file stays unchanged; Copy/Save remain explicit actions.

**Save as (.png / .jpg / .webp)…** exports the latest finalized capture through a
native save dialog. Choose the format by filename: `.png`, `.jpg`/`.jpeg` or
`.webp`. **Settings → Default Save as format** controls the suggested filename and
the format added when no extension is entered (PNG by default). An explicit
extension overrides that preference. Set JPEG quality from 1 to 100 under
**Settings → JPEG export quality** (default 90; click **Save quality** to apply).
JPEG requires opaque pixels; choose PNG or lossless WebP to preserve transparency. JPEG/WebP are export
copies: they keep the current image and PNG library unchanged. PNG exports retain
the existing save/history behavior, and already saved PNGs stream without decoding
or re-encoding. Unsaved captures export directly from retained pixels.
Existing files are never replaced, including after native overwrite confirmation.
Cancel/error preserves the source, clipboard and default folder; Quit waits for
active export. The editor's direct Save actions still use PNG.

Under the latest capture, **Save as size** offers **Original**, **50%**, **25%** or
**Custom width**. Custom width accepts physical pixels up to the source width;
the height follows the aspect ratio, rounded up. Upscaling is rejected.
Smaller sizes reduce both dimensions, rounding up to whole pixels, and are always
export copies — including PNG. The current image, PNG library and clipboard stay
unchanged. Choose Original for the usual full-size save behavior. This choice is
for the current app session; it does not resize the editor canvas or quick captures.

**Upload image** sends the last saved PNG, or the latest in-memory capture if nothing was saved, only after you explicitly click the button. The editor **Upload** action flattens the current document to PNG, keeps it in memory, and does not write a library file or copy the clipboard. First use **Choose destination…** with a JSON file based on [the destination example](docs/upload-destination.example.json), replacing its placeholder URL with your service. **Import ShareX…** loads a documented [`.sxcu` subset](docs/upload-destination.sharex.example.sxcu) (HTTPS ImageUploader, POST multipart, [POST JSON](docs/upload-destination.sharex-json.example.sxcu) or PUT binary, `{json}` / `{header}` / `{response}` / `{responseurl}` / [ `{regex:pattern}` ](docs/upload-destination.sharex-regex.example.sxcu) / [ `{xml:xpath}` ](docs/upload-destination.sharex-xml.example.sxcu) with an optional [HTTPS prefix/suffix](docs/upload-destination.sharex-composed.example.sxcu), [ThumbnailURL/DeletionURL](docs/upload-destination.sharex-extras.example.sxcu), Headers, Parameters, Arguments and Body JSON Data string maps) into this session only; `{base64}` is the only JSON file placeholder, and secrets plus `{input}`/`{filename}`/RegexList/lookaround/`{xml}` without a path/`{xml:input|xpath}` are rejected. **Export ShareX…** writes that same subset for the current session destination; secrets and credential references stay out of the file and existing files are never overwritten. By default this uploader sends a multipart POST. A [PUT destination](docs/upload-destination.put.example.json) uses method: "PUT" to send the PNG directly as image/png with a known Content-Length; field is only used for POST and defaults to file. PUT sends If-None-Match: * so a conforming server rejects an existing target with HTTP 412. Configure a fresh resource URL for each new file; server enforcement must be verified for your endpoint. Unsupported method names are rejected. Configure the field name and choose a JSON pointer, a [plain-text response](docs/upload-destination.text.example.json), a [response header](docs/upload-destination.header.example.json), a [regex](docs/upload-destination.regex.example.json), or an [XML path](docs/upload-destination.xml.example.json) for the returned HTTP(S) link. For text/header/regex/xml mode omit json_pointer; supplying both is rejected. Text responses may have leading/trailing whitespace. Header names are case-insensitive; missing or repeated link headers are rejected. Header mode requires a successful HTTP status and does not follow redirects or read the response body. A regex pattern is 1–256 bytes, compiled in linear time; `group` is an index 0–8 or a name, and a missing match fails the upload. Lookaround stays rejected. An XML path is 1–256 bytes, starts with `/`, and is a bounded XPath subset (child steps, `[n]`, optional `@attr` or `text()`); DTD, `//`, `*` and `{xml:input|xpath}` stay rejected. For PUT endpoints returning no link, use [request-URL mode](docs/upload-destination.put-status.example.json): response type request_url returns the configured resource URL only after HTTP 200, 201 or 204. It rejects POST, 202/pending results, redirects and failures. This is a storage address, not a guarantee of a publicly readable share link; configure a direct file URL and use server-provided links when your service creates separate sharing addresses. For a response like {"url":"https://host/image"}, use /url; nested responses can use /data/url. JSON numbers are accepted as decimal text. When the service returns only an id, set [link_prefix and link_suffix](docs/upload-destination.composed.example.json) so `/id` plus `https://cdn.example/` and `.png` becomes the share link; the composed URL must keep the prefix origin. Optional [thumbnail and deletion parsers](docs/upload-destination.extras.example.json) reuse that JSON-pointer, text, header, regex or XML subset. A successful upload shows them for **Copy thumbnail** and **Copy deletion** in this session only; they are not stored in upload history, and the app never fetches the thumbnail or calls the deletion URL. PUT request-URL mode cannot combine with extras. A configured extra that is missing from the response fails the upload. A loaded destination initially stays in memory for this session. **Remember** saves the validated, credential-free profile beside the app settings as the current destination; it is restored on a worker when the control window is first opened after restart. **Save named…** stores the current session destination under a 1–64 byte name in a separate catalog of at most 16 profiles (`upload-destinations.json`); saving the same name replaces it. **Use** applies a saved name to this session only. **Per-task destination** assigns a saved name to Primary display, Quick region, Capture and annotate, Active window, Repeat last region or Active display; starting that capture applies the name to this session only and never starts an upload. Empty keeps the current session destination. **Remove** deletes only that catalog entry and leaves the session destination, the remembered current file and OS credentials unchanged. **Forget destination** still leaves named destinations in place. **Export configuration** writes the session destination and named catalog to a JSON file you choose ([example](docs/upload-configuration.example.json)); secrets stay out of the file and existing files are never overwritten. **Import configuration** replaces the remembered current destination and named list from such a backup; it does not copy OS credentials, settings.json, history or images. Capture/hotkey readiness never waits for it, and restoring never starts an upload. **Forget destination** disables uploads immediately and removes the saved profile. If removal fails, the UI reports that it may return after restart. **Set up destination** can create a credential-free POST or PUT endpoint without a JSON file. On Windows, **Save credential** then stores a Bearer, API-key or Basic secret in Credential Manager for that HTTPS origin; the destination file keeps only a non-secret reference. **Remove credential** deletes that OS secret and makes the session destination anonymous; **Forget destination** still leaves the OS secret in place. **Test destination** sends a throwaway 1×1 PNG through the same path without recording history or changing the last capture; the server may keep that test image. A successful test shows the returned link for **Copy link**; failure keeps the previous link. It supports anonymous endpoints and [Windows Bearer/API-key/Basic credentials](docs/upload-authentication.md), HTTPS by default and anonymous HTTP only with explicit allow_http: true. Credential profiles reference a generic Windows credential bound to the HTTPS origin. Omit authentication for legacy Bearer behavior, or set authentication: "api_key" for X-API-Key, or authentication: "basic" for a stored username/password. Credentials are never stored in JSON. A destination JSON may include up to 8 custom request headers (1–64 byte names, 1–256 byte values, no `{` `}` `$` templates). Authorization, X-API-Key, Cookie, Content-Type, Accept-Encoding and other transport names stay reserved for credentials and the existing request path. It may also include up to 8 query parameters in `query` (1–64 letter/digit/`_`/`-` names, 1–256 byte values, no templates). Names such as `api_key`, `key`, `token` and `password` stay reserved. The URL field still rejects embedded query strings and fragments; parameters are appended only when sending, and the composed URL stays within 2,048 bytes. Extra POST multipart text fields live in `form` (same name/value bounds and reserved names, at most 8, and they cannot reuse the file field). PUT destinations reject a nonempty `form` map. JSON request bodies live in `json` ([example](docs/upload-destination.json.example.json); same name bounds, at most 8, POST only, exactly one value `{base64}` for STANDARD base64 of the PNG). Extra form fields and JSON bodies cannot be combined. PUT destinations reject a nonempty `json` map. Embedded URL credentials and proxies are not supported in this slice; unknown JSON fields are rejected.

Uploads stream the saved PNG without image decoding, preserve its existing bytes/metadata unless **Strip metadata on upload** is enabled, and use the generic filename screenshot.png for multipart POST (PUT has no multipart filename). **Strip metadata on upload** is a saved setting (default off). When enabled, saved-file uploads re-encode PNG pixels on a worker and drop ancillary chunks such as comments and EXIF; the original file is unchanged. Editor **Upload** and unsaved captures already send pixels only. This is not forensic deletion, and library **Export selected** still copies stored bytes. JSON destinations read that PNG once, encode STANDARD base64 into the `{base64}` field and send `application/json` with a known Content-Length. No upload occurs during capture/editing. The upload status reports PNG bytes read into the request, with at most four intermediate updates per second plus start/end. Once all PNG bytes are prepared it shows Awaiting server response; this does not claim server receipt or success. Updates are event-driven, coalesce to the latest value and add no polling timer. **Cancel upload** stops the request; a server may already have received the image, and cancellation does not remove remote files. Redirects and retries are disabled. The upload has 5-second connect and 60-second overall deadlines, a 1 MiB response cap and one active job. A returned link is displayed but never automatically opened or copied; **Copy link**, **Copy thumbnail** and **Copy deletion** explicitly change the clipboard. Other authentication methods and macOS/Linux secret-store integration remain pending. **Upload history** retains successful links locally across restarts, with source filename, destination origin and date. It loads only on request, 20 rows per page with **Latest**/**Older**. **Copy link** explicitly changes the clipboard; **Remove entry** removes only local metadata and never contacts the provider or deletes remote files. Full source paths and image pixels are not stored in upload history. Returned links, including signed query strings, are stored as-is in the local application database; forgetting a destination does not erase these entries. History-write failure is reported separately and keeps the successfully returned link available.

**Region in 3 seconds** starts a cancellable countdown before freezing the desktop, useful for opening menus first. Use **Cancel countdown** or Escape while the control window has focus. Closing the control window or quitting cancels the pending countdown. Other captures and folder/export actions are blocked during the delay. Its task is dropped on cancellation; no periodic timer remains when idle.

**Capture history** shows saved captures across restarts, 20 entries per page. Choose **All**, **Captures** (app-saved outputs, including exports) or **Imports** (manually added PNG references). **Older** and **Latest** stay within the selected filter; changing filters starts at the latest page. Filters remain responsive during a page fetch, cancel obsolete requests and coalesce to the latest choice; they are disabled during history writes/import selection. Hiding history releases its loaded rows and cancels outstanding fetches; reopening loads the latest page of the remembered filter. Use **Older** and **Latest**, then **Open**, **Show file**, or **Copy** on an entry. **Remove entry** removes only its history metadata and keeps the PNG unchanged. Use **Select** on rows or **Select all** for the current page, then **Remove selected** to remove up to 20 references atomically; **Clear selection** resets the selection. Changing pages/filters or hiding history clears selection. Bulk removal reports the actual count and keeps all image files; a database failure rolls back the entire batch. Copying runs on a worker with the same decode/size limits as last-capture recopy; it does not change the selected last capture. It records newly saved captures and Save As exports; existing image folders are not automatically imported. The local SQLite database stores metadata and file references, not image blobs. Opening/filtering history uses indexed SQLite keyset queries (at most 21 metadata rows, including lookahead); it does not decode images/thumbnails or scan folders. The source index is added by a non-destructive schema migration. The search field matches word prefixes in file paths/names, stored dates (for example 2026-11) and sources; all words must match. It is case-insensitive and accepts up to 16 words/512 UTF-8 bytes. Escape clears search. Filters and Older/Latest stay within the query; hiding history clears it. Search uses a lazily migrated FTS5 index, cancels obsolete queries and retains the same 21-row limit; it never reads image files. Arbitrary substring and OCR search remain pending. **Relink PNG…** lets you point an entry at a moved or replacement PNG through the native picker. It preserves the entry ID, date and original source category, updates dimensions, and never changes image files. Duplicate exact paths, invalid PNG headers and stale entries are rejected. Canceling leaves history unchanged. This is an explicit reassignment, without automatic content matching or folder scanning; automatic reconciliation and retention controls remain pending. Database errors are reported separately from PNG save results.

**Upload PNG** on an entry in Capture history manually uploads that saved file to the currently loaded destination. It works for app captures and imported PNGs, preserves the current last capture, and uses the same single-upload limit, cancellation, progress and upload history as Upload saved PNG. The file path is captured at the click; browsing another page afterward does not redirect the upload. Stored bytes and existing PNG metadata are sent unless **Strip metadata on upload** is enabled. Use **Edit a copy** and save it first when you need a newly edited image.

**Preview** on a history entry shows an aspect-preserving image up to 400×240 pixels without opening another application. Only a clicked entry is decoded, on a worker; one thumbnail is retained. **Hide preview**, changing pages/filters/search or closing history releases it. Preview never changes the PNG, clipboard or history and uses the existing image-size limit. Decoding temporarily holds the full source image; automatic thumbnail loading/prefetch remains pending.

**Export selected…** copies up to 20 selected history images into a folder chosen through the native picker. Original filenames and PNG bytes/metadata are preserved. Existing targets or duplicate filenames are reported as failures; no file is overwritten. **Cancel export** stops remaining work and discards the unfinished copy while keeping completed ones. The result reports exported/failed/not-exported counts. Export streams bytes on one worker without decoding pixels and leaves originals, clipboard, last capture and history unchanged. A confirmed export may continue while history is hidden; quitting requests cancellation and waits for cleanup.

**Add PNGs…** inside Capture history adds references to up to 100 selected existing PNG files through the native picker. This is useful for older files under 	arget/captures. It checks PNG headers and the decoded-size admission limit without decoding full image frames; it does not copy, move or alter originals. Exact paths already listed are skipped. The result reports added/existing/skipped counts and up to three file errors. Valid selections are committed in one metadata transaction; invalid files are skipped with errors. Moving or deleting an original later makes its history reference unavailable. Full pixel decoding happens only when explicitly copying an image.

**Edit a copy** opens the last capture or a selected history entry (including imported PNGs) in the basic editor. Drag rectangles over sensitive content; **Undo** removes the last rectangle, **Redo** restores it, and **Reset** clears crop, annotations and undo/redo state. A new rectangle after Undo discards the redo branch. Editor shortcuts: Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y (Command+Z / Command+Shift+Z on macOS). **Save and copy** applies opaque black RGBA pixels on a worker, exports a new flattened `redacted-<uuid>.png` in the configured save folder and copies that result. Existing original files and history entries remain unchanged and may still contain sensitive content; the editor states this explicitly. **Cancel**/Escape closes without exporting. Quit discards unexported editor changes. The first tool supports up to 100 rectangles, fits the image to the window and cancels an in-progress drag on resize. Annotation undo stores rectangle metadata, not full-image snapshots. New captures wait until editing is finished or canceled. The UI and interaction design remain provisional.

**Frame** in the editor draws rectangular shapes in **Outline** or **Filled** mode, with 1/3/6/12 px source-pixel width for outlines. Choose Red, Yellow, Green or Black; the selected color applies to new frames. Frames, redactions and crop share Undo/Redo and the combined 100-annotation limit. The preview and PNG export use the same four border segments. Frames are drawn below opaque redactions, and crop excludes all pixels outside the selected output. Frame-only exports use `annotated-<uuid>.png`. No raster image is copied while placing a frame.

**Duplicate** in Select, or **Ctrl+D** (**Cmd+D** binding on macOS), copies the selected frame, arrow, ellipse, highlight, pen stroke, text/number, blur, pixelation or redaction. It selects the copy and offsets it by ten source pixels where possible, moving inward near image edges; a full-image mark can remain in place. Drawing copies enter the front of the drawing stack, while source effects and opaque redactions retain their fixed stages. One Undo removes the copy and Redo restores it. Text/pen assets stay shared, and duplicated numbers keep their text without advancing or renumbering the sequence. The action is disabled during a drag, text draft or text preparation and at the combined 100-mark, pen-point or cumulative text export-mask limit; the toolbar explains resource-limit failures. It creates no new pixel buffers, textures, preparation jobs or clipboard/file changes.

**Hold Shift while drawing** to make a square Frame/Highlight/Redact/Blur/Pixelate/Crop region or a circular Ellipse, and to snap Arrow direction to horizontal, vertical or 45-degree diagonals. The starting corner/tail stays anchored and the result is clamped to source-image bounds. Constraints use source pixels, including fractional zoom and unequal display mapping. Pressing or releasing Shift during a drag updates its preview without moving the pointer; the Shift state at mouse release determines the committed geometry. Releasing Shift restores free drawing. Existing-mark move/resize and Pen behavior are unchanged. Undo/Redo records the finished geometry as usual; there is no extra image work, memory buffer or timer.

**Outline / Filled** applies to new Frame and Ellipse marks or to an existing shape in Select. The choice becomes the creation style for subsequent rectangles/ellipses. A mode change is one metadata-only Undo/Redo step; color, order, dimensions and the stored outline width are retained. Width controls are disabled while Filled is selected and become available again in Outline mode. Filled interiors can be selected directly, while outlined shapes are picked at their borders. Move/resize, recolor, duplicate, delete, Shift squares/circles and the shared 100-mark/100-undo limits work in both modes. A filled rectangle uses one GPU rectangle, and a filled ellipse uses its existing outer contour; no bitmap/texture/job is added. Use the dedicated Redact tool for sensitive information.

**Width** is shared by Pen, Frame, Ellipse and Arrow: choose **1, 3, 6 or 12 source pixels** (default 3) before drawing, or select an existing mark and use the same controls. The choice also becomes the width for subsequent drawing marks. Changes support Undo/Redo without pixel snapshots or image work, and moving/resizing/recoloring retains the mark width. Arrow heads scale with width and adapt to short arrows; picking follows the same visible arrow polygon used by preview/export, including wide heads. Hollow frame/ellipse picking follows the chosen inset border. Opaque redactions and filled highlights do not expose stroke width.

**Arrow** draws from the drag start toward the release position, including horizontal, vertical and reversed drags. It shares Red/Yellow/Green/Black with Frame, crop clipping and the combined 100-annotation/100-undo-step limits. Preview and raster export use the same polygon vertices. Arrows follow the shared annotation order below opaque redactions. Handle sizes remain constant on screen while zooming. Like movement, resizing previews metadata only and commits one undo step on release.

Control/Alt/Command/Windows combinations keep their existing meanings. A source-aligned color grid is computed once per editor document on a worker, using alpha-weighted colors. Large-image preview can have softer block boundaries than the full-resolution export. The grid is retained outside undo states; no new image copies are stored per edit. Closing cancels preparation and removes its atlas image. It never saves the unedited original as an intermediate step.
**Blur (B)** adds source-aligned, alpha-weighted 17x17 box blur in the frozen overlay and standalone editor. Choose it and drag after the one-time worker preparation completes. Blur regions share Select, move/resize, Delete, keyboard nudges and bounded Undo/Redo. The effect reads original pixels around the region/crop, so resizing or cropping does not introduce seams. Overlapping Blur regions do not increase blur strength. Pixelate takes priority where both source effects overlap; vector marks and opaque redactions remain above both effects. Blur is visual obscuring, not reliable removal of sensitive information; use **Redact** for that.

Blur preparation retains one preview bounded to 1024 pixels per side (at most 4 MiB). Preview samples the same full-resolution kernel used by export, though downsampling can soften its displayed detail. The separable streaming implementation uses a 288 KiB row buffer instead of a full-resolution filtered copy. Choose 16/24/36 source-pixel text size, Red/Yellow/Green/Black and optional **Bold** / **Italic**. The tool stays active for the next click; the counter advances only after successful placement and is restored by Undo/Redo together with the mark. **Restart numbering** starts a new sequence at 1 without changing existing labels and is itself undoable. Deleting or editing a placed label does not renumber other labels. Select a number to move, resize, reorder, delete or use **Edit text**. Numbers share the existing text asset/memory and 100-mark limits; rendering runs on the existing worker with cancellation, and export uses the normal flattened text path. These are plain numbered labels, without circular badges. Wait for preparation to finish before the next click; no click backlog is created.

**Text (T)** adds labels with up to four lines and 512 UTF-8 bytes total directly in the frozen overlay and standalone editor: click the image, type, choose 16/24/36 source-pixel type size, Red/Yellow/Green/Black and optional **Bold** / **Italic**, then **Enter** or **Apply text**. **Shift+Enter** adds a line break; there is no automatic line wrapping. Blank and trailing lines are preserved. Use **Select → Edit text** to change an existing label; moving, resizing, deleting, keyboard nudges and Undo/Redo use the shared document model. Resizing scales the prepared mask; applying size/style changes prepares native glyphs again. Style edits support Undo/Redo, and duplicates retain their shared styled assets. Native shaping/rasterization stays on the existing worker with the same memory/job limits. Pending drafts are never silently exported. The input grows to four rows and supports Unicode/UTF-16 native composition, row-aware pointer/IME caret geometry, grapheme-aware navigation/deletion, Up/Down, line Home/End, Ctrl/Cmd+Home/End for the whole block, selection, clipboard shortcuts and bounded input Undo/Redo. Manual typing/IME and mixed-DPI acceptance remain open.

Labels use the existing native GPUI font system and system UI font/fallbacks, without loading another font runtime. Shaping and monochrome coverage rasterization run on a worker; preview and export share the same immutable mask. Emoji are monochrome in the chosen ink color. The worker deliberately avoids the Windows color-glyph path because it drives the UI's shared D3D immediate context. Glyph work is serialized with effect preparation, canceled/stale-checked on close or text cancellation, and never runs on every mouse move. Text is limited to 512 UTF-8 bytes per line and a 1024×128-pixel prepared mask. Labels that cannot fit the image report an error. The document admits at most 200 retained text assets / 4 MiB of combined masks and BGRA previews; unreachable assets are pruned before admission and Reset/close drops their atlas images. Undo shares assets; it never copies screenshot pixels. Text follows the shared annotation order below opaque redactions. Only flattened pixels reach PNG/history/clipboard output; editable text is not written as extra PNG metadata.
**Layer order:** new pen strokes, highlights, frames, arrows, ellipses and text appear above earlier drawing marks. In **Select**, use **Bring forward** / **Send backward** to move the selected mark by one layer. Selection, live drag previews and flattened export use the same order. Reordering is undoable, changes metadata only and does not create image copies or jobs. Controls are disabled at the front/back boundary and for source effects/redactions. Removing a mark updates the remaining references, including through Undo/Redo.
