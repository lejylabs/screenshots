# screenshots

Open-source desktop capture and sharing application. English is the default UI language. Native system dialogs and OS error messages follow the operating system language.

Windows renderer lifecycle and its explicit release probe are documented in [control-window latency](docs/control-open-latency.md). The pinned Windows GPUI backend includes a small [local teardown patch](vendor/gpui-windows-gpui-unofficial/LOCAL-PATCH.md); build through this workspace so Cargo applies the override.

The [region-selection release probe](docs/region-latency.md) measures native Ctrl+Shift+R delivery through capture and compositor synchronization, with 101 real capture/cancel cycles. Its explicit test injects keyboard input; leave keyboard and clipboard untouched while running it. Normal launches contain no probe instrumentation.

On Windows, normal launches share one instance per user/session. Starting the app again signals the running instance to show its control window and exits before creating another tray icon or registering hotkeys. Instance setup/notification failures do not fall back to launching a second owner. A newly created control window is explicitly shown, including after a launcher started the resident app hidden. Explicit resource-probe modes and isolated GUI tests bypass this product lifecycle.

## Capture home

Open the control window with `cargo run -p screenshots -- --show` (Windows otherwise starts in the tray). The home screen offers region selection, primary/all displays, individual displays and window capture. The last capture has a bounded preview, recopy and **Show file**. Technical controls are under **Diagnostics**.

New captures use the user's Pictures/Screenshots folder by default (application config storage is the fallback if no Pictures directory is available). **Change folder…** opens the native directory picker and persists the selection in the platform application's `settings.json`. A canceled or failed change preserves the previous folder. Settings load/save run on workers; capture is disabled while settings are loading/changing. Existing files under `target/captures` are left in place. Hardware tests keep their isolated test directories and do not read or alter user settings.

**Save as…** exports the last capture through a native save dialog. PNG is the export format; existing files are never replaced, including after an overwrite confirmation from the native picker. Choose a free name if a destination already exists. Saved PNGs stream directly to the new destination without image decoding/re-encoding; unsaved captures export from their retained pixels. Canceling preserves the capture, clipboard and default folder. Quit waits for an active export, and export failure keeps the source available.

**Upload saved PNG** sends the last saved image only after you explicitly click the button. First use **Load destination…** with a JSON file based on [the destination example](docs/upload-destination.example.json), replacing its placeholder URL with your service. By default this uploader sends a multipart POST. A [PUT destination](docs/upload-destination.put.example.json) uses method: "PUT" to send the PNG directly as image/png with a known Content-Length; field is only used for POST and defaults to file. PUT sends If-None-Match: * so a conforming server rejects an existing target with HTTP 412. Configure a fresh resource URL for each new file; server enforcement must be verified for your endpoint. Unsupported method names are rejected. Configure the field name and choose a JSON pointer, a [plain-text response](docs/upload-destination.text.example.json), or a [response header](docs/upload-destination.header.example.json) for the returned HTTP(S) link. For text/header mode omit json_pointer; supplying both is rejected. Text responses may have leading/trailing whitespace. Header names are case-insensitive; missing or repeated link headers are rejected. Header mode requires a successful HTTP status and does not follow redirects or read the response body. For a response like {"url":"https://host/image"}, use /url; nested responses can use /data/url. A loaded destination initially stays in memory for this session. **Remember destination** saves the validated, credential-free profile beside the app settings; it is restored on a worker when the control window is first opened after restart. Capture/hotkey readiness never waits for it, and restoring never starts an upload. **Forget destination** disables uploads immediately and removes the saved profile. If removal fails, the UI reports that it may return after restart. It supports anonymous endpoints and [Windows Bearer/API-key/Basic credentials](docs/upload-authentication.md), HTTPS by default and anonymous HTTP only with explicit allow_http: true. Credential profiles reference a generic Windows credential bound to the HTTPS origin. Omit authentication for legacy Bearer behavior, or set authentication: "api_key" for X-API-Key, or authentication: "basic" for a stored username/password. Credentials are never stored in JSON. Embedded URL credentials, URL queries, custom headers and proxies are not supported in this slice; unknown JSON fields are rejected.

Uploads stream the saved PNG without image decoding, preserve its existing bytes/metadata, and use the generic filename screenshot.png for multipart POST (PUT has no multipart filename). No upload occurs during capture/editing. The upload status reports PNG bytes read into the request, with at most four intermediate updates per second plus start/end. Once all PNG bytes are prepared it shows Awaiting server response; this does not claim server receipt or success. Updates are event-driven, coalesce to the latest value and add no polling timer. **Cancel upload** stops the request; a server may already have received the image, and cancellation does not remove remote files. Redirects and retries are disabled. The upload has 5-second connect and 60-second overall deadlines, a 1 MiB response cap and one active job. A returned link is displayed but never automatically opened or copied; **Copy link** explicitly changes the clipboard. Other authentication methods and macOS/Linux secret-store integration remain pending. **Upload history** retains successful links locally across restarts, with source filename, destination origin and date. It loads only on request, 20 rows per page with **Latest**/**Older**. **Copy link** explicitly changes the clipboard; **Remove entry** removes only local metadata and never contacts the provider or deletes remote files. Full source paths and image pixels are not stored in upload history. Returned links, including signed query strings, are stored as-is in the local application database; forgetting a destination does not erase these entries. History-write failure is reported separately and keeps the successfully returned link available.

**Region in 3 seconds** starts a cancellable countdown before freezing the desktop, useful for opening menus first. Use **Cancel countdown** or Escape while the control window has focus. Closing the control window or quitting cancels the pending countdown. Other captures and folder/export actions are blocked during the delay. Its task is dropped on cancellation; no periodic timer remains when idle.

**Capture history** shows saved captures across restarts, 20 entries per page. Choose **All**, **Captures** (app-saved outputs, including exports) or **Imports** (manually added PNG references). **Older** and **Latest** stay within the selected filter; changing filters starts at the latest page. Filters remain responsive during a page fetch, cancel obsolete requests and coalesce to the latest choice; they are disabled during history writes/import selection. Hiding history releases its loaded rows and cancels outstanding fetches; reopening loads the latest page of the remembered filter. Use **Older** and **Latest**, then **Open**, **Show file**, or **Copy** on an entry. **Remove entry** removes only its history metadata and keeps the PNG unchanged. Use **Select** on rows or **Select all** for the current page, then **Remove selected** to remove up to 20 references atomically; **Clear selection** resets the selection. Changing pages/filters or hiding history clears selection. Bulk removal reports the actual count and keeps all image files; a database failure rolls back the entire batch. Copying runs on a worker with the same decode/size limits as last-capture recopy; it does not change the selected last capture. It records newly saved captures and Save As exports; existing image folders are not automatically imported. The local SQLite database stores metadata and file references, not image blobs. Opening/filtering history uses indexed SQLite keyset queries (at most 21 metadata rows, including lookahead); it does not decode images/thumbnails or scan folders. The source index is added by a non-destructive schema migration. The search field matches word prefixes in file paths/names, stored dates (for example 2026-11) and sources; all words must match. It is case-insensitive and accepts up to 16 words/512 UTF-8 bytes. Escape clears search. Filters and Older/Latest stay within the query; hiding history clears it. Search uses a lazily migrated FTS5 index, cancels obsolete queries and retains the same 21-row limit; it never reads image files. Arbitrary substring and OCR search remain pending. **Relink PNG…** lets you point an entry at a moved or replacement PNG through the native picker. It preserves the entry ID, date and original source category, updates dimensions, and never changes image files. Duplicate exact paths, invalid PNG headers and stale entries are rejected. Canceling leaves history unchanged. This is an explicit reassignment, without automatic content matching or folder scanning; automatic reconciliation and retention controls remain pending. Database errors are reported separately from PNG save results.

**Upload PNG** on an entry in Capture history manually uploads that saved file to the currently loaded destination. It works for app captures and imported PNGs, preserves the current last capture, and uses the same single-upload limit, cancellation, progress and upload history as Upload saved PNG. The file path is captured at the click; browsing another page afterward does not redirect the upload. Saved bytes and existing PNG metadata are sent unchanged. Use **Edit a copy** and save it first when you need a newly edited image.

**Preview** on a history entry shows an aspect-preserving image up to 400×240 pixels without opening another application. Only a clicked entry is decoded, on a worker; one thumbnail is retained. **Hide preview**, changing pages/filters/search or closing history releases it. Preview never changes the PNG, clipboard or history and uses the existing image-size limit. Decoding temporarily holds the full source image; automatic thumbnail loading/prefetch remains pending.

**Export selected…** copies up to 20 selected history images into a folder chosen through the native picker. Original filenames and PNG bytes/metadata are preserved. Existing targets or duplicate filenames are reported as failures; no file is overwritten. **Cancel export** stops remaining work and discards the unfinished copy while keeping completed ones. The result reports exported/failed/not-exported counts. Export streams bytes on one worker without decoding pixels and leaves originals, clipboard, last capture and history unchanged. A confirmed export may continue while history is hidden; quitting requests cancellation and waits for cleanup.

**Add PNGs…** inside Capture history adds references to up to 100 selected existing PNG files through the native picker. This is useful for older files under 	arget/captures. It checks PNG headers and the decoded-size admission limit without decoding full image frames; it does not copy, move or alter originals. Exact paths already listed are skipped. The result reports added/existing/skipped counts and up to three file errors. Valid selections are committed in one metadata transaction; invalid files are skipped with errors. Moving or deleting an original later makes its history reference unavailable. Full pixel decoding happens only when explicitly copying an image.

**Edit a copy** opens the last capture or a selected history entry (including imported PNGs) in the basic editor. Drag rectangles over sensitive content; **Undo** removes the last rectangle, **Redo** restores it, and **Reset** clears crop, annotations and undo/redo state. A new rectangle after Undo discards the redo branch. Editor shortcuts: Ctrl+Z, Ctrl+Shift+Z / Ctrl+Y (Command+Z / Command+Shift+Z on macOS). **Save and copy** applies opaque black RGBA pixels on a worker, exports a new flattened edacted-<uuid>.png in the configured save folder and copies that result. Existing original files and history entries remain unchanged and may still contain sensitive content; the editor states this explicitly. **Cancel**/Escape closes without exporting. Quit discards unexported editor changes. The first tool supports up to 100 rectangles, fits the image to the window and cancels an in-progress drag on resize. Annotation undo stores rectangle metadata, not full-image snapshots. New captures wait until editing is finished or canceled. The UI and interaction design remain provisional.

**Frame** in the editor draws rectangular shapes in **Outline** or **Filled** mode, with 1/3/6/12 px source-pixel width for outlines. Choose Red, Yellow, Green or Black; the selected color applies to new frames. Frames, redactions and crop share Undo/Redo and the combined 100-annotation limit. The preview and PNG export use the same four border segments. Frames are drawn below opaque redactions, and crop excludes all pixels outside the selected output. Frame-only exports use `annotated-<uuid>.png`. No raster image is copied while placing a frame.

**Duplicate** in Select, or **Ctrl+D** (**Cmd+D** binding on macOS), copies the selected frame, arrow, ellipse, highlight, pen stroke, text/number, blur, pixelation or redaction. It selects the copy and offsets it by ten source pixels where possible, moving inward near image edges; a full-image mark can remain in place. Drawing copies enter the front of the drawing stack, while source effects and opaque redactions retain their fixed stages. One Undo removes the copy and Redo restores it. Text/pen assets stay shared, and duplicated numbers keep their text without advancing or renumbering the sequence. The action is disabled during a drag, text draft or text preparation and at the combined 100-mark, pen-point or cumulative text export-mask limit; the toolbar explains resource-limit failures. It creates no new pixel buffers, textures, preparation jobs or clipboard/file changes.

**Hold Shift while drawing** to make a square Frame/Highlight/Redact/Blur/Pixelate/Crop region or a circular Ellipse, and to snap Arrow direction to horizontal, vertical or 45-degree diagonals. The starting corner/tail stays anchored and the result is clamped to source-image bounds. Constraints use source pixels, including fractional zoom and unequal display mapping. Pressing or releasing Shift during a drag updates its preview without moving the pointer; the Shift state at mouse release determines the committed geometry. Releasing Shift restores free drawing. Existing-mark move/resize and Pen behavior are unchanged. Undo/Redo records the finished geometry as usual; there is no extra image work, memory buffer or timer.

**Outline / Filled** applies to new Frame and Ellipse marks or to an existing shape in Select. The choice becomes the creation style for subsequent rectangles/ellipses. A mode change is one metadata-only Undo/Redo step; color, order, dimensions and the stored outline width are retained. Width controls are disabled while Filled is selected and become available again in Outline mode. Filled interiors can be selected directly, while outlined shapes are picked at their borders. Move/resize, recolor, duplicate, delete, Shift squares/circles and the shared 100-mark/100-undo limits work in both modes. A filled rectangle uses one GPU rectangle, and a filled ellipse uses its existing outer contour; no bitmap/texture/job is added. Use the dedicated Redact tool for sensitive information.

**Width** is shared by Pen, Frame, Ellipse and Arrow: choose **1, 3, 6 or 12 source pixels** (default 3) before drawing, or select an existing mark and use the same controls. The choice also becomes the width for subsequent drawing marks. Changes support Undo/Redo without pixel snapshots or image work, and moving/resizing/recoloring retains the mark width. Arrow heads scale with width and adapt to short arrows; picking follows the same visible arrow polygon used by preview/export, including wide heads. Hollow frame/ellipse picking follows the chosen inset border. Opaque redactions and filled highlights do not expose stroke width.

**Arrow** draws from the drag start toward the release position, including horizontal, vertical and reversed drags. It shares Red/Yellow/Green/Black with Frame, crop clipping and the combined 100-annotation/100-undo-step limits. Preview and raster export use the same polygon vertices. Arrows follow the shared annotation order below opaque redactions. Arrow export temporarily allocates one output-sized premultiplied RGBA overlay with a source-clamped one-pixel raster gutter for crops in addition to the final output buffer, composites it onto straight RGBA while preserving untouched pixels, then releases it before PNG/clipboard work. The gutter is limited to 4 MiB within the existing active-image scratch allowance; no updated latency/memory acceptance is claimed from unit tests.

Editor view controls: **+ / −** zoom, **100%** maps an image pixel to a physical display pixel using the window DPI, and **Fit** restores the centered full-image view. Use the wheel/trackpad to pan enlarged images and Shift+wheel for horizontal movement. Panning is clamped to the image edges and disabled during an annotation drag. Zoom/resize cancels an unfinished drag; document coordinates, undo history and export dimensions are unaffected by view changes. The workspace clips the enlarged image below the toolbar. Zoom uses the existing texture and adds no decoded image copies or background work.

**Ellipse** adds red/yellow/green/black ellipses in **Outline** or **Filled** mode, with a 1/3/6/12 px source-pixel inset border for outlines. Very small ellipses become filled when no interior remains. Preview and export share bounded polygon contours (32–256 segments per contour), crop clipping and the existing output-sized raster overlay. Ellipses participate in the same 100-annotation limit and Undo/Redo. Pen strokes, highlights, frames, ellipses, arrows and text follow creation/reordering order; opaque redactions remain above them. Outline mode leaves the interior visible; use Redact for sensitive content.

**Capture and annotate** opens a frozen fullscreen editing overlay. Crop is selected initially; redact, frame, arrow, ellipse, undo/redo and zoom work directly on the desktop preview before final output. **Move toolbar** switches the toolbar between the top and bottom so every part of the image remains reachable. The source stays in RAM: opening, cropping, annotating or canceling creates no PNG/history entry and does not change the clipboard. **Copy only** exports pixels to the clipboard; **Save only** publishes a PNG and history entry; **Save and copy** does both. Without a crop, explicit output uses the entire captured display. Cancellation preserves the previous last-capture state. The existing **Select region** action retains its immediate save/copy behavior.

On Windows, **Ctrl+Shift+E** and the tray's **Capture and annotate** action open this overlay without the control window. One display is edited per session: the monitor under the pointer, with the primary display as fallback. Ctrl+Shift+S/R retain their immediate capture behavior. Each shortcut registers independently and unavailable shortcuts appear in the status line. The overlay reuses its worker-prepared image; annotations and undo store geometry rather than full-image snapshots. Canceling or finishing output without an open control window removes the overlay and detaches graphics again. A short real-desktop regression checks cancellation, no image/database output, unchanged clipboard and no remaining GPUI windows. Mixed-DPI interaction and physical input/presentation performance still require manual acceptance checks.

**Select** picks existing redactions, frames, arrows and ellipses in the overlay and standalone editor. A cyan outline identifies the selected mark; drag it to move it within the image, or use **Delete**, Delete/Backspace to remove it. Hollow frames/ellipses are selected at their outline. Selection follows the existing visible layer order. Movement is previewed from metadata and becomes one undo step on release; deletion is undoable too. Clicking empty space deselects. Selection outlines and handles are never exported. Drag one of the four corner handles to resize a redaction, frame or ellipse; drag either endpoint handle to change an arrow. The opposite corner/endpoint stays fixed. Rectangle dimensions stay at least one source pixel, arrow endpoints stay distinct, and changes remain within the source image. Handle sizes remain constant on screen while zooming. Like movement, resizing previews metadata only and commits one undo step on release.
Editor/overlay keyboard tools: **V** Select, **X** Redact, **C** Crop, **R** Frame, **A** Arrow and **E** Ellipse. Tool changes discard an unfinished drag. In Select mode, arrow keys move the selected mark by one source-image pixel; **Shift+arrow** moves ten pixels, independent of zoom/DPI. Moves clamp to image boundaries and remain undoable. Control/Alt/Command/Windows combinations keep their existing meanings. The palette in Select mode shows and changes the selected frame/arrow/ellipse color, with Undo/Redo; selecting the same color adds no undo step. Opaque redactions remain black and cannot be recolored. The chosen color also becomes the color for new marks.
**Pixelate (P)** works in the frozen overlay and standalone editor. Choose it, then drag a region after the one-time background preparation completes. Pixelate regions share Select, move/resize, Delete and Undo/Redo, and count toward the combined 100-mark limit. The effect uses fixed 16-source-pixel blocks aligned to the original image; moving a region reveals the blocks at its new position. It affects source pixels below frames, arrows, ellipses and opaque redactions. It does not pixelate those annotation layers. Pixelation is visual obscuring, not reliable removal of sensitive information; use **Redact** for that.

A source-aligned color grid is computed once per editor document on a worker, using alpha-weighted colors. Preview uses a single BGRA image bounded to 2048 pixels per side (at most 16 MiB), clipped to each region, with no rerasterization during dragging. Large-image preview can have softer block boundaries than the full-resolution export. The grid is retained outside undo states; no new image copies are stored per edit. Closing cancels preparation and removes its atlas image. Export flattens source-aligned blocks at full resolution, clips them to the crop and merges overlapping regions so each affected output pixel is written once. It never saves the unedited original as an intermediate step.
**Blur (B)** adds source-aligned, alpha-weighted 17x17 box blur in the frozen overlay and standalone editor. Choose it and drag after the one-time worker preparation completes. Blur regions share Select, move/resize, Delete, keyboard nudges and bounded Undo/Redo. The effect reads original pixels around the region/crop, so resizing or cropping does not introduce seams. Overlapping Blur regions do not increase blur strength. Pixelate takes priority where both source effects overlap; vector marks and opaque redactions remain above both effects. Blur is visual obscuring, not reliable removal of sensitive information; use **Redact** for that.

Blur preparation retains one preview bounded to 1024 pixels per side (at most 4 MiB). Preview samples the same full-resolution kernel used by export, though downsampling can soften its displayed detail. The separable streaming implementation uses a 288 KiB row buffer instead of a full-resolution filtered copy. Pixelate and Blur preparations share one active job and one latest pending request; closing cancels preparation and drops both optional atlas images. Export processes the union of Blur regions, clipped to the chosen output, off the UI thread. No PNG or disk handoff is used.
**Number (N)** places sequential text step markers (`1.`, `2.`, `3.`, ...) with one click in the frozen overlay or standalone editor. Choose 16/24/36 source-pixel text size, Red/Yellow/Green/Black and optional **Bold** / **Italic**. The tool stays active for the next click; the counter advances only after successful placement and is restored by Undo/Redo together with the mark. **Restart numbering** starts a new sequence at 1 without changing existing labels and is itself undoable. Deleting or editing a placed label does not renumber other labels. Select a number to move, resize, reorder, delete or use **Edit text**. Numbers share the existing text asset/memory and 100-mark limits; rendering runs on the existing worker with cancellation, and export uses the normal flattened text path. These are plain numbered labels, without circular badges. Wait for preparation to finish before the next click; no click backlog is created.

**Text (T)** adds labels with up to four lines and 512 UTF-8 bytes total directly in the frozen overlay and standalone editor: click the image, type, choose 16/24/36 source-pixel type size, Red/Yellow/Green/Black and optional **Bold** / **Italic**, then **Enter** or **Apply text**. **Shift+Enter** adds a line break; there is no automatic line wrapping. Blank and trailing lines are preserved. The text block must still fit the existing 1024×128-pixel glyph mask; use fewer lines or a smaller font when it is too tall. **Escape** first cancels the text draft. Use **Select → Edit text** to change an existing label; moving, resizing, deleting, keyboard nudges and Undo/Redo use the shared document model. Use **Select → Edit text** to change font style on an existing label or number, then Apply text. Bold and Italic may be combined and are applied when the label is prepared. Resizing scales the prepared mask; applying size/style changes prepares native glyphs again. Style edits support Undo/Redo, and duplicates retain their shared styled assets. Native shaping/rasterization stays on the existing worker with the same memory/job limits. Pending drafts are never silently exported. The input grows to four rows and supports Unicode/UTF-16 native composition, row-aware pointer/IME caret geometry, grapheme-aware navigation/deletion, Up/Down, line Home/End, Ctrl/Cmd+Home/End for the whole block, selection, clipboard shortcuts and bounded input Undo/Redo. CRLF/CR paste and composition text normalize to LF with matching UTF-16 offsets. Adding a fifth line is rejected without changing the text or undo history. Manual typing/IME and mixed-DPI acceptance remain open.

Labels use the existing native GPUI font system and system UI font/fallbacks, without loading another font runtime. Shaping and monochrome coverage rasterization run on a worker; preview and export share the same immutable mask. Emoji are monochrome in the chosen ink color. The worker deliberately avoids the Windows color-glyph path because it drives the UI's shared D3D immediate context. Glyph work is serialized with effect preparation, canceled/stale-checked on close or text cancellation, and never runs on every mouse move. Text is limited to 512 UTF-8 bytes per line and a 1024×128-pixel prepared mask. Labels that cannot fit the image report an error. The document admits at most 200 retained text assets / 4 MiB of combined masks and BGRA previews; unreachable assets are pruned before admission and Reset/close drops their atlas images. Undo shares assets; it never copies screenshot pixels. Text follows the shared annotation order below opaque redactions. Only flattened pixels reach PNG/history/clipboard output; editable text is not written as extra PNG metadata.
**Layer order:** new pen strokes, highlights, frames, arrows, ellipses and text appear above earlier drawing marks. In **Select**, use **Bring forward** / **Send backward** to move the selected mark by one layer. Selection, live drag previews and flattened export use the same order. Reordering is undoable, changes metadata only and does not create image copies or jobs. Controls are disabled at the front/back boundary and for source effects/redactions. Blur and Pixelate remain source effects below drawing marks; opaque Redact remains the final layer. Editing a text label retains its layer position. Removing a mark updates the remaining references, including through Undo/Redo.

The ordered exporter reuses one lazily allocated output-sized vector layer, with a one-pixel crop gutter clamped to the source bounds. The gutter keeps antialiasing at crop edges consistent with the full-image result; its additional bytes count against the existing scratch allowance and are capped at 4 MiB. Extreme long/narrow crops exceeding that cap report an error before vector allocation. Before a frame or text label is painted directly, only its touched region is composited and cleared in that layer; remaining vectors are flushed once at the end. This preserves straight-alpha text/color handling without allocating an image per layer. The shared text/highlight/spotlight compositor uses exact short paths for opaque ink and fully transparent/opaque destination pixels, reducing export CPU work without extra buffers or jobs. Fixed Blur/Pixelate source-effect order remains a separate release gate for arbitrary effect ordering.
**Spotlight (S)** keeps a rectangular focus area clear and dims the surroundings in the frozen overlay or standalone editor. Drag its focus area; hold Shift for a square. The default is Black at 75% opacity; choose 25/33/50/75/100% and a palette color for a tint. Select inside the focus rectangle to move/resize, recolor, change opacity, reorder, duplicate or delete it, with Undo/Redo. It shares the 100-mark limit with other annotations. A spotlight follows the drawing stack: earlier marks can be dimmed, later marks remain above it, and multiple spotlights compose in order. Opaque Redact always paints last; use Redact for sensitive content. The preview uses at most four non-overlapping GPU rectangles, with no bitmap, texture, mask or preparation job. Export blends only those clipped areas into the final output, keeping the focus unchanged. The shared palette now also includes Black for other colored drawings and text.

**Highlight (H)** draws a translucent filled rectangle directly in the frozen overlay and standalone editor, using the current Red/Yellow/Green/Black palette color. Choose **Opacity: 25%, 33%, 50%, 75% or 100%** (default 33⅓%); the same controls in **Select** update an existing highlight with Undo/Redo. Translucent highlights leave content readable; use Redact for sensitive information. Select a highlight to recolor, move, resize, delete, nudge or move it forward/backward in the shared drawing order. All changes support Undo/Redo and share the combined 100-mark limit. New highlights inherit the current drawing color and highlight opacity; choose Yellow for a conventional marker color. The preview is one GPU rectangle and needs no bitmap/cache or background preparation. Export blends only the clipped region into the final image using the same straight-alpha ink compositing as text, flushing earlier vector pixels where required. Opaque redactions still paint last.
**Pen (D)** adds freehand strokes directly in the frozen overlay and standalone editor. Drag to draw and release to commit one undo step; clicking creates a small square dot. Ink uses the current Red/Yellow/Green/Black palette with **Width: 1, 3, 6 or 12 source pixels** (default 3), flat ends and beveled joins. The same width controls in Select change existing strokes with Undo/Redo, retaining shared point assets. Select near the ink to recolor, move, reshape with corner handles, delete, nudge or reorder it. Resizing transforms the centerline and retains the chosen ink width. **Escape** cancels a currently drawn stroke first; a second Escape closes the editor. No raster preview or image job is created while drawing.

Input keeps distinct points at roughly two-source-pixel spacing, with the final point included when space remains. Each stroke admits at most 1,024 sampled points and the visible document at most 8,192 pen points, alongside the existing combined 100-mark limit. If a limit is reached, the toolbar asks you to release or remove marks; the path stops accepting points instead of silently growing or accumulating jobs. Releasing commits the accepted portion. Immutable point lists are shared by Undo/Redo; editing position/size/color does not copy them. Preview and worker export use the same centerline, width and join settings, with crop clipping and opaque redactions last. Export reuses the existing single vector layer. Closing releases stroke data with the document; no point lists are written into PNG/history metadata.
Editor output choices: **Copy only** renders and copies the edited pixels without PNG/history output; **Save only** saves a PNG and records history without touching the clipboard; **Save and copy** does both, keeping independent result statuses. Copy-only output retains at most the last edited RGBA image in RAM for recopy, further editing or Save As, replacing the previous last capture. This is a live document representation, not the empty-resident baseline; it is released when replaced or the app exits. Save success releases the full-resolution source as before. Quit waits for the chosen active output job. A short isolated fixture test verifies Save-only clipboard preservation and Copy-only absence of PNG/history output.

## Build

Requires Rust 1.99.

```bash
cargo build -p screenshots
cargo run -p screenshots
```

On Windows the app starts in the system tray without a control window or GPU renderer. Right-click the camera icon (possibly under hidden icons) and choose **Show control window**. Use `cargo run -p screenshots -- --show` to open it immediately. Closing the control window returns to the tray and detaches the renderer; **Quit** in the tray or Ctrl+Q exits. Other platforms retain the windowed Phase 0 spike.

See [Phase 0 evidence and remaining checks](docs/phase-0.md).

- Open small overlay: red card at the top-left of each display.
- Capture a window: click a listed window near the top of the control window to capture it directly, save it and copy it. Use Fensterliste aktualisieren after opening or closing windows. Minimized, untitled and own-process windows are excluded from the picker. A window that closes before capture produces an error and restores the control window.

Release idle measurement (Windows PowerShell 5.1):

```powershell
cargo build --release -p screenshots
powershell -NoProfile -File scripts/measure-idle.ps1 -Seconds 30
```

Close other screenshots instances first and do not trigger captures or menu actions during sampling. The probe owns only the process it starts, hides its control window, waits five seconds, then samples CPU time/Private Bytes/working set once per second and closes the process normally. Results, binary hash and hardware/source context are written to `target/performance/idle-normal.json`; logs are beside it. CPU is expressed as a percentage of one logical core. Use `-Seconds 300` for the planned five-minute idle duration. A short run on the development PC is exploratory, not a reference-hardware acceptance pass; GPU resources, wakeups, energy and post-capture retention need separate measurement. The script never force-kills an unresponsive process.

Resource attribution probes use the same executable without the normal app services:

```powershell
powershell -NoProfile -File scripts/measure-idle.ps1 -Seconds 30 -Mode headless
powershell -NoProfile -File scripts/measure-idle.ps1 -Seconds 30 -Mode empty
powershell -NoProfile -File scripts/measure-idle.ps1 -Seconds 30 -Mode normal
```

Headless explicitly skips attaching the GPU/window system and creates no tray/hotkeys/capture shell; empty attaches GPUI and creates an empty control-sized window but no app services. These are diagnostics, not fully functional alternative application modes. Each probe exits on a bounded one-shot diagnostic deadline. Windowed modes get one second to render before hiding; all modes then warm for five seconds before sampling. Reports are `target/performance/idle-<mode>.json`, with thread/handle counts and the binary hash. Run modes sequentially; differing first-frame/hide timing and driver warmup can affect results, so do not attribute all differences to one allocation source.

Normal output thumbnails are now at most 400x240 BGRA. Replacing thumbnails and dismissing overlays explicitly removes their image atlas entries. This does not prove the renderer/driver releases atlas backing pages; GPU memory must still be measured. Successful save releases the retained source RGBA buffer; recopy explicitly reloads the saved file on a worker with decode/RGBA limits. A failed save retains pixels so the unsaved image remains available. This on-demand recopy is separate from the capture -> selection -> clipboard pipeline, which remains in memory.
